Watching grpc-epub unpack a book

One HTTP request carries the archive up while events come back down, the same shape as the gRPC call underneath. A ZIP's central directory is its last bytes, so nothing can begin until the upload bar fills — then info arrives before a single chapter is inflated, and each chapter appears as its entry comes off the archive.

The upload throttle delays the upload only; the event pace delays how fast rows are drawn, by pausing the gRPC stream between events. Neither changes what the server does. Try cover-first.epub against two-chapters.epub: same book, but the cover image is stored before the chapters, so its resource event arrives first — a resource is emitted when its archive entry is reached, not in spine order.
